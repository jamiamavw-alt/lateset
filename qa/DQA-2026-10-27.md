# DQA — Lateset prototype vs Figma — 2026-10-27

- **Build:** `prototype/index.html` (885 lines) + `prototype/lateset-tracks.js`, live at https://jamiamavw-alt.github.io/lateset/prototype/ (the live page matches the local source; the size difference is multibyte characters only)
- **Figma:** `l0XOAUabplpYlhWLINg0m7`. Pages used: Color `19:2`, Typography `20:2`, Materials `21:2`, Layout `22:2`, Motion `35:336`; screens `156:2079` (Live), `156:2305` (Schedule), `156:2476` (Live Player), `156:2618` (Playing), `156:2962` (Profile); 14 component descriptions via `search_design_system`
- **Rules:** `DESIGN.md` v1.0.1, `AGENTS.md`, `CLAUDE.md`
- **Method:** Figma read-only tools, the built-in browser at 390×1000, 375×812 and 430×932, `getComputedStyle`/`getBoundingClientRect` probes, `~/.claude/agents/dqa/audit.js` (pasted in as an inline copy), a 16-step keyboard Tab walk, and the Motion toggle. Contrast was computed offline from token values, with alpha composited over each wall stop.

---

## 1. Verdict

**Don't ship as the reference build.** It has 4 P0s against the §8 accessibility contract. Three are small CSS fixes. The touch-target one needs a layout change on phones. Token values are clean (0 value drift), but component and screen fidelity to the Page Mocks is loose.

## 2. Scorecard

| Check | Result |
|---|---|
| Tokens matched | **73 / 96**. Every token the build defines matches Figma by value and code-syntax name (0 ❌, 0 ⚠️). 23 semantic/scale tokens are missing (➖). Primitives are not shipped by design. |

## 3. Findings (highest severity first)

### P0: breaks a MUST or the §8 contract

**P0-1 · Touch targets and text shrink below spec on every phone width**
- **Where:** `prototype/index.html:104` (`.stage`), `:399-404` (`fitStage`); Figma `size/touch-min` (44), Icon Button `11:16` ("Round 44×44")
- **Expected:** "Every tappable thing MUST be at least `size/touch-min` (44×44)", and the layout must work at 375/390/430 (AGENTS DoD).
- **Actual:** the 390×844 phone is scaled with `transform: scale(--s)`. Measured `--s` and the rendered size of a 44px icon button:

  | Viewport | `--s` | 44px button renders at | 10px badge text renders at |
  |---|---|---|---|
  | 375×812 | 0.795 | **35.0px** | 8.0px |
  | 390×1000 | 0.918 | **40.4px** | 9.2px |
  | 430×932 | 0.937 | **41.2px** | 9.4px |

- **Fix:** on phone-sized viewports, render the phone full-bleed at 1:1 and drop the device chrome:
  ```css
  @media (max-width: 500px) {
    body { padding: 0; }
    .note-bar { display: none; }
    .stage { width: 100vw; height: 100dvh; }
    .phone { width: 100vw; height: 100dvh; transform: none; border-radius: 0; border: 0; box-shadow: none; }
  }
  ```
  and in `fitStage()`: `if (innerWidth <= 500) { $('stage').style.setProperty('--s', 1); return; }`
- **Twin:** none (layout only).

**P0-2 · Past schedule slots and removed saved sets fail text contrast**
- **Where:** `:212` `.slot.past { opacity: .55; }`, `:253` `.saved.removed … { opacity: .45; }`; Figma Schedule Slot `16:116` ("Past = faded to 55%")
- **Expected:** §8 says text contrast ≥ 4.5:1.
- **Actual** (composited over the bottom wall stop `#f3a7c5` through Glass/Card): past-slot secondary text **2.80:1**, past-slot ink **3.21:1**, removed-row secondary text **2.29:1**.
- **Fix:** fade the decoration, not the text:
  ```css
  /* before */ .slot.past { opacity: .55; }
  /* after  */ .slot.past .tile { opacity: .55; }
               .slot.past .title-md, .slot.past .time { color: var(--color-ink-muted); }
  ```
  For `.saved.removed`, keep the text at full opacity, dim only the tile, and swap the bookmark icon (already done).
- **Twin:** Figma Schedule Slot `16:116` State=Past and Saved Set Row `16:146` Saved=False. This is a **source conflict** (see §4); Figma's 55% rule needs to change too.

**P0-3 · Genre-chip focus ring is clipped top and bottom**
- **Where:** `:175` `.chips { … padding: 2px var(--spacing-6); overflow-x: auto; }`; the same pattern in `.favs` at `:246` (`padding: 0 … var(--spacing-1)`)
- **Expected:** §8 says "Visible focus ring: 2px `color/text/primary`, 3px offset."
- **Actual:** the ring needs 5px outside the chip, but the scroller gives it 2px. In a zoomed screenshot of a focused "Techno" chip, only the left and right arcs of the ring are visible. The ring spec itself is correct (`2px solid rgb(82,11,44)`, offset 3px, on all 16 stops walked).
- **Fix:**
  ```css
  .chips { padding: var(--spacing-1_5) var(--spacing-6); margin-block: calc(-1 * var(--spacing-1)); }
  .favs  { padding: var(--spacing-1_5) var(--spacing-6) var(--spacing-1); }
  ```
- **Twin:** none.

**P0-4 · Text cannot scale to 200%**
- **Where:** every type rule uses `px` (`:125-133`, `:165`, `:177`, `:209-210`, `:257`), the phone is fixed at `height: 844px` (`:106`), and rows use `overflow: hidden; white-space: nowrap` (`.clip`, `:135`)
- **Expected:** §8 says "Layout survives 200% text size without clipping."
- **Actual:** setting `document.documentElement.style.fontSize = '200%'` leaves `.title-md` at 16px. No `rem` or `em` sizes exist anywhere in the build.
- **Fix:** move the type ramp to `rem` (16px base: `.title-md { font-size: 1rem }`, `.badge { font-size: .625rem }`, and so on), let `.phone` grow with `min-height` instead of a fixed `height` on the full-bleed phone layout from P0-1, and let `.row` titles wrap to 2 lines instead of truncating at large sizes.
- **Twin:** Figma Typography text styles (no change needed; this is a code-only unit change).

### P1: visible drift from Figma

**P1-1 · Play Button has no Dark (stopped/paused) state, and its icon is ink instead of berry**
- **Where:** `:232` `.big-play { background: var(--color-control); }` (no state rule); markup at `:524` and `:558`. Figma Play Button `11:31`.
- **Expected:** "Light = currently playing (white button, berry icon). Dark = stopped/paused (berry button, white icon)."
- **Actual:** listening = `bg rgb(255,255,255)`, `color rgb(82,11,44)` (ink). Stopped = the same white. The Playing screen opens paused and also shows white.
- **Fix:**
  ```css
  .big-play { color: var(--color-accent); }
  .big-play[data-state="off"] { background: var(--color-accent); color: var(--color-on-accent); }
  ```
  Set `data-state` from `st.liveOn` / `st.playing` in `paintLiveState()` (`:576`) and `paintPlayButton()` (`:581`).
- **Twin:** Play Button `11:31` (already correct).

**P1-2 · On the Live Player, the Up Next row sits under the tab bar on open**
- **Where:** `:217` `.art { width: 100%; aspect-ratio: 1 }`, `:132` `.caption` (no `margin: 0`), `:224` `.live-status` padding; Figma Live Player `156:2476`
- **Expected:** the whole screen fits: panel ≈ 596px, Up Next Row, then the tab bar 20px above the bottom.
- **Actual:** the panel measures **667.5px**. Most of the extra height comes from three places: cover **298×298** vs **260×260**; `<p class="caption">` picks up the browser's default 12px top and bottom margins, which makes Live Status **83px tall** (Figma ≈ 56px); and Live Status padding is 12/16 vs 10/14. The screenshot shows the tab bar covering "Mirae Song · Ambient".
- **Fix:**
  ```css
  .caption { margin: 0; }
  .art.deep { width: 260px; align-self: center; }   /* or add a size/art token; ask first */
  .live-status { padding: var(--spacing-2_5) var(--spacing-3_5); background: var(--glass-fill-raised); }
  ```
- **Twin:** Album Cover `13:9` / Live Status `11:68`. If a fixed 260 is intended, it needs a `size/*` token (ask before adding one).

**P1-3 · The Live screen shows 1 Up Next row; Figma shows 3**
- **Where:** `:434-439`; Figma Live `156:2079` → Up Next `I156:2079;156:868`
- **Expected:** Up Next Row ×3 (Mirae Song 10:00 PM, Theo Vance 11:30 PM, Ezra Bloom 1:00 AM). Row padding 12/16. Eyebrow time 11px ExtraBold, `color/text/secondary`, uppercase, +0.08em. Title `Title/Small` 15px.
- **Actual:** 1 row. Time is `.time` 15px/800 ink with no uppercase; title is `.title-md` 16px; padding 12/12.
- **Fix:** render `SLOTS.filter(s => s.state === 'next')` with the Up Next Row markup used on the Live Player (`:526-530`), and change the time span to `<span class="eyebrow" style="font-size:11px; font-weight:800; color:var(--color-ink-muted)">`. Better still, add an `.eyebrow-sm` class so no inline px is needed.
- **Twin:** Up Next Row `16:147`.

**P1-4 · Tab Bar position and inactive label color**
- **Where:** `:256` `.tabbar { bottom: var(--spacing-4) }`, `:257` `.tab` (color inherits ink), `:258` `.tab svg { 22px }`; Figma Tab Bar `12:208`, Tab Item `12:19`
- **Expected:** "Sits 16px from the screen edges and **20px above the bottom**." Default label = "muted ink" (`color/text/secondary`). Icon 24px, gap `spacing/0-5`.
- **Actual:** bottom 16px; inactive color `rgb(82,11,44)` (primary); icon 22px; gap 3px.
- **Fix:**
  ```css
  .tabbar { bottom: var(--spacing-5); }
  .tab { color: var(--color-ink-muted); gap: var(--spacing-0_5); }   /* needs --spacing-0_5 added, see token table */
  .tab svg { width: 24px; height: 24px; }
  ```
- **Twin:** Tab Bar `12:208`.

**P1-5 · Deep cover eyebrow and Blush cover title fall below contrast minimums**
- **Where:** `:218-219`, eyebrow at `:511`; Figma Album Cover `13:9`
- **Expected:** "Deep keeps white text at 4.5:1+"; Blush titles reach 3:1.
- **Actual:** white on `color/art/deep-start` (#df4f88) = **3.74:1**, and the 12px eyebrow sits in the top-left corner, where the gradient is about 3.8–4.0:1. White on `color/art/blush-start` (#eb7ba7) = **2.65:1**. Where the first title line sits (35% down the cover), the gradient is about **2.99:1**.
- **Fix:** this is on the Figma side. Darken `color/art/deep-start` to `pink/500` (#d2296f, 4.90:1), and start Blush at `pink/400` instead of `pink/300`. No code change is needed beyond the token values.
- **Twin:** variables `color/art/deep-start`, `color/art/blush-start`.

**P1-6 · Schedule Slot type sizes cause truncation not present in Figma**
- **Where:** `:211` `.slot .when { width: 76px }`, `:451-452` (`.title-md` / `.body-sm`), `:191` `.list { gap: spacing-3 }`; Figma Schedule `156:2305`
- **Expected:** title `Title/Small` 15px; subline `Label/Caption` 12px/600; time column 66px; list gap `spacing/2-5` (10px).
- **Actual:** 16px, 13px/500, 76px, 12px gap. The screenshot shows "Late Bloom · Hou…", "Soft Static · Amb…", "Night Shift · Tec…" truncated; Figma shows them in full.
- **Fix:** `.slot .title-md → class="title-sm"`, `.slot .body-sm → class="caption"`, `.slot .when { width: 66px }` (Figma clips "10:00 PM" at 66px, so 72px is the safer choice; see §4), and `#slot-list, .saved-list { gap: var(--spacing-2_5) }`.
- **Twin:** Schedule Slot `16:116`.

**P1-7 · Badge padding**
- **Where:** `:165` `.badge { gap: 5px; padding: 2px var(--spacing-1_5) }`; the Live Dot variant is inline at `:507` (`font-size:11px;padding:3px 10px`). Figma Badge `10:10`.
- **Expected:** Live/On Air padding `spacing/0-5` × `spacing/2` (2×8). Live Dot padding `spacing/1` × `spacing/2-5` (4×10), gap `spacing/1-5`, 11px.
- **Actual:** 2×6 with gap 5px; the Live Dot variant is 3×10 with gap 5px, all hard-coded.
- **Fix:**
  ```css
  .badge { gap: var(--spacing-1_5); padding: var(--spacing-0_5) var(--spacing-2); }
  .badge.lg { font-size: 11px; padding: var(--spacing-1) var(--spacing-2_5); }
  ```
  Then replace the inline style at `:507` with `class="badge lg"`.
- **Twin:** Badge `10:10`.

**P1-8 · Profile: live favorites are not first**
- **Where:** `:357` `FAVS = ['zb','ml','jl','ms','jr']`
- **Expected:** §6: first thing the eye hits is "Favorite DJs who are live". Page Mock spec says "Favorite DJs (live first)".
- **Actual:** Jamie Rose (LIVE) is 5th and clipped at the right edge at 390px.
- **Fix:** `const FAVS = ['zb','ml','jr','jl','ms'];`, or sort: `FAVS.sort((a,b) => DJ[b].live - DJ[a].live)`.
- **Twin:** Profile screen `156:963` (Screen component). The Figma mock has the same wrong order (see §4).

**P1-9 · Glass Icon Button and Live Status are fill-only (not the full glass recipe)**
- **Where:** `:202` `.ib.flat { background: var(--glass-fill-control) }` (no stroke); `:224` `.live-status` (fill only, and the wrong level). Figma Icon Button `11:16` Style=Glass.
- **Expected:** Glass = `glass/fill/control` + 1px `glass/stroke/default`. Live Status = `glass/fill/raised`. §4: "Fill alone is not glass."
- **Actual:** bell, shuffle-on and repeat-on have `border-top-width: 0`; Live Status uses `rgba(255,255,255,.35)` (chip level).
- **Fix:** `.ib.flat { background: var(--glass-fill-control); border: 1px solid var(--glass-stroke); }`. For `.live-status`, see P1-2.
- **Twin:** Icon Button `11:16`.

## 4. Source conflicts (Jamie's call)

1. **Cover title size.** The Figma text style `Display/Cover` = Syne 22px, -4%, and `Display/Cover Small` = 24px, -2%. The Typography doc row (`20:39`) says "Syne ExtraBold · 34px / 87.9". The build uses up to 34px. Which is right?
2. **Past-slot fade vs contrast.** The Figma Schedule Slot says "Past = faded to 55%". DESIGN §8 requires text ≥ 4.5:1 (measured 2.80 / 3.21). Keep the fade on the tile only?
3. **Chip height.** Figma Genre Chip is "40px tall pill (touch area extends to 44px with row gap)". DESIGN §4 says "Every tappable thing MUST be at least 44×44"; a gap doesn't add hit area. Make chips 44, or add an invisible 44px hit box?
4. **Toggle-ON style.** DESIGN §4: "A toggle that is ON → Icon Button / Filled + the filled icon." Figma: Repeat (on) = Glass style (Playing `156:932`); heart and bookmark ON = Ghost with a filled icon ("Ghost: like, bookmark"). The build follows Figma.
5. **Glass inside glass.** DESIGN: "MUST NOT put glass inside glass. Inside a glass panel, use flat content or solid controls." Figma puts `glass/fill/control` bells inside Glass/Card slots, Live Status (`glass/fill/raised`) inside the Glass/Subtle panel, and Repeat (glass) inside the Playing panel.
6. **Saved Set mini-cover gradient.** Figma binds `color/genre/<g>` → `color/art/deep-end`. DESIGN: "MUST bind both stops to the tokens" (`color/genre/<g>` → `color/genre/<g>-end`). The build uses genre → genre-end.
7. **Live favorites order.** The Profile mock spec text says "live first", but the mock itself orders ZB, DM, JL, MS, **JR (live)**. DESIGN §6 agrees with the spec text.
8. **Live card count.** The Live mock shows **5** cards (including "DJ Design Agent", 10k, Pop), but its spec says "×4 · one per DJ on air". The build has 4.
9. **Album Cover contrast claim.** The Figma description says "Deep keeps white text at 4.5:1+", but `color/art/deep-start` gives 3.74:1 (see P1-5).
10. **Figma-side defects (no conflict, just fix in Figma):** the Live Dot badge uses `radius/scale/lg` directly (DESIGN: semantic radius only), and the Schedule time column (66px) clips "10:00 PM" in the Schedule mock.

## 6. Not checked

- **Purple mode values and the mode list.** `get_variable_defs` returns only the resolved (Pink) mode, and the read-only tools can't list collection modes. Confirming Purple needs `use_figma` (write-capable, so it was not used) or Jamie checking in Figma.
- **Code-syntax names for `size/*`, `motion/*` and `blur/glass/sm`.** These variables aren't bound on any doc node `get_variable_defs` could read, so their names are marked "assumed". Their values come from the variable descriptions.
- **The real 200% text zoom experience** (iOS Dynamic Type / browser text zoom). Only the px-vs-rem cause was verified.
- **Real audio** (Spotify/SoundCloud embeds) was not played. Live/stop state was checked with the simulated timer and DOM state only.
- **Screen-reader output** (VoiceOver/NVDA). ARIA attributes and live regions were inspected in the DOM only.
- **`audit.js` contrast pass:** it skipped all 33 text nodes on glass/gradient backgrounds (it can't composite alpha over gradients). Contrast in this report is computed from token values instead.
- The toast's 5-second auto-dismiss (WCAG 2.2.1 timing) was not formally assessed.
